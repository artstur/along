# Bug#1 · 新建目标缺少返回入口

## 正确行为

新链路中的“新对话”是一份尚未形成目标的对话草稿，不应成为无法退出的页面。用户在空白、已输入、正在发送、发送失败或已收到回复时，都必须能通过同一个标准返回组件离开对话。

返回时优先回到进入新对话前的已存目标；没有已存目标时回到简洁的目标首页。已经落入本地队列的用户消息不删除，对话关联号不改写，后续 Agent 结果仍写回原对话所属的目标，不得覆盖当前正在查看的其他目标。

## 范围与方案

- 只修改 `web/` 的新链路对话导航与对应测试，不改 Agent 输出校验、事件封装或健康数据边界。
- 复用现有 `backButton()` 和 `agent-back` 行为，保持 44 点可点区域及 iOS 侧滑返回接线。
- 新对话持久记住进入前的已存目标；未发送文字按新对话或已存目标分开保存，只在消息成功落入本地队列后清除。首句发送后继续输入的第二句草稿也跟随原会话恢复。返回不清理已持久化的草稿、消息、队列或同步游标。
- 用户可见修复完成后同步提高 Web、Service Worker 和 iOS 壳的资源版本，由 `npm run build` 生成两份产物。

## 验收标准

1. 新对话空白、已有本地草稿、队列待发、发送失败及收到回复时均显示标准返回图标。
2. 返回图标及 iOS 左缘侧滑返回到原目标；无原目标时返回无对话组件的首页。重开对应对话时，首发前草稿和首句发送后的未发送补充都仍在。
3. 返回后队列中的原消息、对话 ID 和后续回复关联不变；新目标同步回来时不自动抢走当前已存目标。
4. 旧目标“聊聊这个目标”的返回、输入框键盘布局和选择目标流程不回归。

# TASK-75 · 新建选项文案

## 正确行为

App「新建」旁边的目标下拉框里，那个空值选项就是「新建目标」的入口：它把用户带进新目标的对话流程。所以它必须显示「新目标」，显示「新对话」会让人以为进的是一条没有目标的普通对话。

选项值仍是空字符串，选中条件不变，`data-action="new-goal"` 的点击行为也不变——点「新建」继续走现有的新建对话流程。这一轮只改文案。

## 范围与方案

- 只改 `web/app.mjs` 里目标下拉框空值选项的显示文案，不改选项值、选中条件与事件处理。
- 同步提高 Web、Service Worker 和 iOS 壳的资源版本，由 `npm run build` 生成 `dist/` 与 `ios/AlongHealth/Web/` 两份产物。
- iOS 重新安装 App 需要，`CFBundleVersion` 一并提高。
- 回归测试放在 `test/app-new-goal-label.test.mjs`：钉住空值选项显示「新目标」，以及点「新建」后仍进入新建对话流程。

## 验收标准

1. 目标下拉框的空值选项显示「新目标」，页面上不再出现「新对话」。
2. 点「新建」仍然进入现有的新建对话流程，输入框与返回入口都在。
3. `npm run check` 全绿；`npm run build` 后 `dist/` 与 `ios/AlongHealth/Web/` 和 `web/` 内容一致。
4. 四处版本号同步提高：Web `?v=`、Service Worker `CACHE`、iOS 壳 `build=`、`CFBundleVersion`。

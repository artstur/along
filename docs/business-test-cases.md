## 1. 范围与口径

### 1.1 覆盖范围

- 阶段 A–E 的业务可观察行为，加上 D1–D17 决策边界的可判定断言。
- **不覆盖**：模型内部策略与提示词效果、DSH 核心机制内部实现、Hy-Memory 检索算法内部逻辑、视觉稿级 UI 细节、阶段 0 的技术探针（见 [阶段 0 技术验证](https://github.com/artstur/along-superagent/blob/feature/along-phase0/docs/along/004-phase0-validation.md)）。
- 只在特定阶段才存在的用例，在该阶段到达前记「不适用（阶段未到）」，不按失败计。

### 1.2 硬判定口径

- 每条用例至少给出一条**可观察、可判断、有唯一答案**的断言。可观察对象：`along.sqlite` 业务状态、DSH Store 记录（Trigger / Decision / Mandate / Ticket / Assignment / Effects）、iPhone 界面与本地待同步队列、批次作业状态、执行记录、通知与提醒。
- 不接受「看起来正常」「表现良好」这类描述。写不出唯一答案的，回到规格补齐后再落用例。
- 涉及计数的断言写具体数字，例如「本轮未产生第二次模型调用」用 DSH 模型调用计数核对，不靠印象。

### 1.3 编号规则

`BC-<组号>-<两位序号>`。组号见 §2；阶段与优先级单列。阶段取 A–E，未标注即 B。

### 1.4 执行环境与造数

- **Mac**：Along Host、DSH fork（`along` Source 走 `auto` 规则）、`along.sqlite`；批次作业按阶段 0 选定的调度方式配置。
- **iPhone**：已配对；健康摘要一律用合成数据，不接真实 HealthKit 原始样本；理财用演示数据。
- **造数入口**：合成摘要与事件统一从服务端事件入口注入并记录 `event_id`，不绕过接收校验直接改库，避免造出真实链路不会出现的状态。
- **账号**：首期单用户（D1）。涉及归属检查的用例需要第二个 `user_id` 的构造数据，由测试数据脚本直写，不开放注册。

| BC-02-07 | 任务取消与调整 | 有未完成任务 | 通过聊天要求取消或改期 | 任务状态按语义变更并记录生成依据；已收到的完成反馈不被覆盖 | 架构 §5.1 | B·P2 |

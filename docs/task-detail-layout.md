# 动态任务详情与执行记录

本轮用户要求产品仍只有目标、任务、连接数据源三个主要模块，数据源在页面底部。推荐方案属于对应动态任务，不能另占首页模块。任务卡显示执行时间、有效定时任务标记和查看详情；详情显示实际执行次数与该任务结果。

## 范围与实现

- 事件工作台按目标 → 动态任务 → 连接数据源排列。现有目标聊天只保留直接对话。
- 使用稳定的目标和任务身份进入现有工作台的任务详情，推荐按两者精确归属，保留来源与分别过期状态、方案反馈。通知进入同一详情。
- 卡片不展开内部提醒依据；提醒规则、需要补充的信息和真实系统安排仍在详情。执行时间与提醒时刻分别说明。
- 执行次数由宿主可证明的任务执行证据投影，不能用模型调用、版本、消息数或重试计数。推荐研究、提醒任务、实际生活动作按各自任务语义判定；真实预约／徒步不能因提醒已发而写作已完成。开发验收来源不计自然业务执行。
- 旧缓存和旧消息保持兼容；缺少可信执行证据时不伪造次数。原目标、任务、排程、配对、用户对话与推荐正文不变。

## 验收

1. 首页无独立推荐模块，数据源位于所有任务之后。
2. 进入对应任务详情看到它的方案、来源、执行次数，其他目标或任务的方案不串入。
3. 非定时任务不标定时，时间未定如实展示；有效周期与时区保留。
4. 推荐通知打开正确任务详情，返回任务列表、方案反馈和直接聊天正常。
5. 真正重复执行增加次数，重试／重启／重复提交不重复累计；实际动作与提醒分开。
6. 全量检查、构建及两端资源一致，主线签名更新原手机并分别登记自动回执与用户实际观察。

主分类 ui；上游 data/agent 执行记录投影先合并，随后客户端验证，最后 client/release 统一部署。

执行次数标题使用“已记录 N 次执行”：它是已有可信产出／完成事实的数量，不宣称覆盖所有历史失败尝试。资料在交付时是否有效与此后TTL过期分别判断，日后过期不会抹掉历史已确认执行。

## 入口与详情密度修正

用户继续要求“查看详情”只是浅灰色小文字链，详情不要大字号。入口复用原有语义按钮和点击处理，去掉实心按钮样式；保持键盘焦点与足够透明点击高度。仅给任务详情增加局部密度类：标题20px、正文14px、执行记录标题16px、推荐标题17px并收紧卡片与段落间距，不改首页其他字体。最新数据源主线与执行／时效／聊天／通知规则保持。

验收用390px真实浏览器测量入口透明背景与浅灰文字、详情标题字号和无横向溢出，并复核查看详情／返回／方案反馈可用。

## 状态与详情入口对齐

用户继续要求状态与“查看详情”右对齐、同字号，去掉下划线并加小右箭头。卡片复用原身份和操作，把状态与入口放到同一右侧栏；两者12px，入口保持浅灰透明文字，装饰chevron不进入可访问名称。保留原左侧标题／执行时间／定时标签和卡片高度，不改后台或计数契约。常态、hover、focus均无下划线，键盘焦点仍可见。390px真实浏览器核对两者右边线、字号和实际点击／键盘进入详情。

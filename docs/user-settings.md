# 用户设置页

## 1. 目标与范围

Along iPhone App 缺一个统一入口：用户要设置昵称、查看并管理数据源授权、确认与服务端的配对与连接状态，只能在各个功能页里找。设置页把这三件事收在一处，并复用既有流程，不新造连接逻辑。

本单范围（对应工单 TASK-88）：

- 从 App 内进入设置页，页面上能看到昵称、数据源、Along 服务三段与各自当前状态。
- 昵称可设可改，持久化在 App 内；改昵称不影响 UID 与配对关系。
- 数据源沿用既有授权流程（Apple Health 走原生 HealthKit 桥接，OKX 走既有设备来源流程），失败时显示实际状态并可重试。
- 服务端沿用既有配对与连接检查流程；未配对用户可在设置页完成配对，已配对用户升级后继续可用。

不在本单范围：周六晨起称重提醒（另立需求）；服务端保存昵称（见 §6 待确认项）。

## 2. 昵称的归属规则

昵称是显示名，不是身份。它复用既有用户身份，不另建账号体系：

| 情形 | 昵称归属 | 表现 |
| --- | --- | --- |
| 尚未配对 | 记在本机（`userId` 为 `null`） | 本机可见 |
| 已配对 | 属于该身份（`userId`） | 只有该身份可见 |
| 配对确认身份后 | 从本机认领到该身份 | 昵称跟着走，UID 与配对关系不动 |

三条硬约束：

- **改昵称不改 UID。** 昵称记录与身份记录分开存放，写昵称不碰 `along.event-connection.v1`，也不碰配对凭据。
- **改昵称不破坏配对。** 配对关系、token 与绑定作用域都不受昵称操作影响。
- **昵称不跨身份泄漏。** 换个身份登录就看不到上一个人的昵称。

实现见 `web/user-profile.mjs`（纯逻辑）与 `web/app.mjs` 的存取部分。

## 3. 入口

顶部栏右侧的个人入口就是设置入口：显示昵称；没设昵称时显示身份标识；两者都没有就显示「设置」。设置页有返回按钮，返回到进入前的那一页。

入口放在所有页面的顶部栏（含首页、目标详情、任务详情），因为这三项都是跨目标的全局状态，放在某一页里就找不到。

## 4. 设置页的三段

一屏只服务一个主要任务，所以三段各自独立、互不嵌套。

### 4.1 昵称

一个输入框加保存按钮。输入做清洗：去控制字符、去首尾空白、最长 24 字。清空昵称等于删除记录本身，不留空记录。

下方一行说明当前身份（`u_xxxxxxxx`）或说明「还没配对，昵称先存在本机」。

### 4.2 数据源

列出 App 已支持的数据源，每项显示当前状态与一个操作按钮：

- **Apple Health**：状态来自原生桥接的真实读取状态（未连接 / 检查中 / 读取失败 / 演示数据 / 已导入 / 已连接），操作走既有的 `connect-health` 流程——原生弹层选类型、预览、导入。
- **OKX**：只在当前目标确实带这个数据源时出现（它按目标授权，不是全局开关），状态取既有设备来源查询结果，操作走既有的 `event-okx-connect` 流程。

操作按钮的文案跟着状态走：未连接是「连接」，已连接是「管理」，读取失败是「重试」。授权被拒或被撤销时显示实际状态，不假装已连接。

### 4.3 Along 服务

一张状态卡加配对入口：

- 未配对：显示「未配对」并直接给出配对表单（服务地址 + 一次性连接码）。
- 已配对：显示地址与连接状态（已连接 / 检查中 / 连接需处理 + 失败原因），有「重试」按钮，以及可展开的「重新配对」表单。连接中断时额外给出「只更新服务地址」表单。

配对走既有 `/pair` 与原生 Keychain 凭据存储；「重试」走既有 `/connection/status` 检查。

## 5. 验收标准

以 iOS 实际操作为准：

- 能从 App 内进入设置，看到三段与当前状态。
- 新用户能设昵称，已有用户能改；重启后显示最近一次保存的值；原 UID 仍有效，配对关系不变。
- 数据源能授权、能连接；拒绝授权、撤销授权或连接失败时页面显示实际状态并可重试。
- 未配对用户能在设置页完成配对与连接；已配对用户升级后能继续连接；配对失败或连接中断有明确状态并可重试。

自动化覆盖见 `test/user-profile.test.mjs`（昵称规则）与 `test/app-settings-page.test.mjs`（页面行为，含重启后仍显示）。

## 6. 待确认项

- **服务端是否也要保存昵称。** 本轮昵称只存在 App 内，Mac 侧的 Agent 看不到它。若要让 Agent 用昵称称呼用户，需要服务端存一份并随身份下发，这要动 Host 与 Along Agent 的接口与存储，属于另一轮改动。
- **昵称是否需要同步到其他设备。** 同上，取决于上一项。
- **OKX 在设置页的入口粒度。** 本轮按当前目标显示；是否要改成按设备聚合，等目标模型定下来再说。
